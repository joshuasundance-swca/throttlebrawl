CI's checks wait less, and test the same things. The browser tests now run in four parallel slices instead of two, and the sim batch's two slices are split by each test file's measured CI time (`tests/timings.json`, refreshed with `node scripts/timings.mjs <run-id>`) instead of by file count, which had left one sim slice at about 290 s and the other at 120 s. Every test file still lands in exactly one slice, and each slice fails if its runner ran a different number of files or tests than planned. The last browser slice runs perf on its own build instead of building twice; static and unit share one job; Chromium's system packages are kept between runs, because the Ubuntu mirror sometimes took 5 to 8 minutes to send them; and the Playwright browser cache no longer resets on every lock-file change. `dev-presets.test.ts` computes the Easy and Hard batches while another file computes the Normal one, instead of all three in a row. For the local loop, `npm run test:changed` runs only the unit and sim tests a change touches, and `npm run e2e:one -- <spec>` builds and runs one browser spec (docs/engineering.md, "Local loop for lanes"). The gate's list of checks is unchanged.

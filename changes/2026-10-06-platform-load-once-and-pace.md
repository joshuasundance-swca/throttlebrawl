A first visit downloads each of the game's files once, picking a region asks the game server for its map files a few at a time, and a new version going live in the middle of your race no longer breaks a part of it with an error. Three fixes from the last live check:

- On a first visit, 30 files still came down twice (260,032 bytes): scripts the game opened before it had finished saving itself for offline play, and models it saved before the game asked for them. Each now comes down once.
- Picking San Francisco asked the game server for all 34 of its map files at once, and the server answered some of them "too many requests". The game now asks for 4 at a time, and when the server asks it to wait, every file still in line waits.
- When a new version went live mid-race, the race lost its landmarks with two errors on the page. A part of the scenery that does not load is now tried once more, the race goes on without it if that fails too, and the result screen offers the reload to the new version as before.

For devs: punch items 1, 4 and 5 of polish batch F's live check. (1) On a first visit (no older build's cache) the offline worker's install asks for every `.js` file normally, lazy ones included (`downloadHashed` in `src/platform/offline-worker.ts`): one the page imported revalidates (a 304 from the host's ETag), and one it did not comes plain, which the page's later `import()` revalidates in turn. While no worker controls the page, the page's own `fetch()` of a file under `assets/` reads the offline caches first (`readsOfflineCaches`, new `src/platform/page-cache.ts`, wrapped around `retryingFetch` in `startOffline`), so a model or map file the install took as its gzip copy is not downloaded again. The cost is a lazy script the page never loads comes plain: on build `c2afc12` and the live check's visit, 195,114 bytes plain for 36 such scripts against 78,599 as copies, while the install no longer downloads 187,791 bytes of copies for the 27 lazy scripts the page did load, and the page no longer downloads 3 models (40,780 bytes): about 112 KB less on that visit, not the full 260 KB. (5) `retryingFetch` (`src/platform/retry-fetch.ts`) asks for no more than `FETCH_LANES` (4) build files at a time; a request holds its lane until the host's answer arrives, and a 429's `Retry-After` is set before the lane is handed on, so every file in line waits it out (polish batch E's wait rule). (4) New `loadChunk` (`src/content/lazy-chunk.ts`, exported from `src/content/`): a lazy chunk's import tried once more after 1 s, then a console warning and `null`, never a rejection. Every `import()` in `src/render/` (the landmarks, models, roadside, scenes, the backdrop and the other per-road chunks, the vehicles, the race parts, the rider rigs, the film pass) and the race HUD's heat badge in `src/ui/index.ts` use it; render/ asks again for a chunk that failed both tries only at the next `setRoad`, so the race parts and the film pass are no longer asked for every frame while a gone build answers 404. A build whose files are gone still reaches the stale-build watch through Vite's `vite:preloadError`, fired for each failed try.

Playing offline no longer loses Fred the Tree, Coit Tower or other lazily loaded parts when an update went out while the game was saving itself for offline play. The game now saves a whole version or nothing: if an update lands part way through, that save is thrown away, the last complete one stays in charge, and the next launch saves the new version. If a tab left open across an update finds a part of the game gone, it reloads once to the current version instead of racing on without it.

For devs: `[default]`, not phone-verified, no local browser run (CI runs `tests/e2e/app-offline.spec.ts`). Playtest 4 run A's live check, mustFix 2 and punch item 11; the details are in `docs/engineering.md`, Deploy, Offline.
- **All or nothing** (`createOfflineWorker`'s `install` in `src/platform/offline-worker.ts`): any file that fails (a 404 once a deploy has replaced the build, a connection dropped twice) fails the install and deletes this build's cache, so the worker never activates with a hole in it. Before, only `index.html` had to cache, which is how a tab ended with 650 of 668 files.
- **Only its own build**: `workerConfig` in `scripts/service-worker.mjs` now hands the worker a check for each file outside `assets/`: its SHA-256, or for `index.html` the entry script it loads. A page cannot be checked by its bytes because the game Space adds a script of its own to HTML (live `index.html` 5,172 bytes against the Space repo's 5,071; the other four files match their SHA-256 byte for byte, checked 2026-10-05). At run time only `changelog.json` is kept from the network; before, an online launch after a deploy wrote the newer build's page and chunks into the older build's cache.
- **A stale chunk reloads once**: `reloadOnStaleChunk` in `src/platform/index.ts` listens for Vite's `vite:preloadError` and reloads the page once per build id (session storage), never with the network off. `startOffline` now takes the build id from `app/` (a one-line change in `src/app/index.ts`).
- **No preload warnings**: the page the worker serves leaves out its `rel=preload` hints (the 37 boot road files). Chrome will not use a preload that a worker answered ("cross-world service worker resource mismatch", `Resource::CanReuse` in Blink), so each hint was a wasted fetch and about 5 warnings. The cached page stays the host's bytes, and the first load, before the worker, keeps its hints. The modulepreloads stay.
- **Tests**: `src/platform/offline-worker.test.ts` simulates a deploy landing after the host has answered 3 of the install's requests. On main's worker the install resolves with Y's page and a hole; here it rejects and leaves no cache, and Y's worker then caches all of Y. The new and changed cases there fail 7 of 14 on main's worker. `src/platform/offline.test.ts` covers the reload (once, not again on the same build, not offline, not without storage); `scripts/service-worker.test.ts` covers the checks. The offline browser spec now also checks that the worker's page has no preload hints (the first load is the control) and that no preload warning is logged.
- **Budget**: first-load JavaScript 479,309 to 479,470 bytes gzip (+161) of 512,000, so 32,530 headroom, from a local `vite build` of each (main's `src/platform/index.ts` and `src/app/index.ts` against this branch's; the worker's `sw.js` is not first-load JavaScript).

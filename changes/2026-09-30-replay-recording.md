replay-1: input recording and playback. The recorder keeps the player slots' quantized inputs per tick, the mid-race tuning changes `{tick, id, value}`, a state hash after every 60th tick and, via `finish()`, the final hash. `beginRace(sim, key)` writes the full header: format version, the replay key (`makeReplayKey(simCodeHash, simContentHash)`; in M1 the code part is the build commit), and the race's whole `SimConfig` as plain data (the road and route handles are rebuilt from the event with `configFromHeader`). `encodeReplay` / `decodeReplay` turn a recording into the run-length-encoded file the debug file carries (a 6,752-tick bot race: 17 KB of JSON including the header, against 338 KB for the plain inputs); a file from a newer format, or with runs that do not add up, is refused. `createReplayController(rec).run(freshSim)` re-applies each tuning change with `sim.applyParam` before stepping its tick, compares every stored hash, and stops at the first desync with its tick. The in-memory `current()` shape is unchanged, so the test handle's `inputs()` keeps working. Replaying real bot races from their file exposed a determinism bug (a `-0` steer), fixed in the sim contract by PR #28.

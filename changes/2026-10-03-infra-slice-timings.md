CI's sim and browser slices are even again. On main run 37157149149 sim slice 1/4 took 537 s of its 10 minutes while slice 2/4 took 269 s, and browser slices 1 and 2 spent 7.6 and 7.8 minutes on e2e while slice 3 spent 4.4. Three causes, three fixes. The timing table now holds the average of four CI runs that already had the new geometry sweeps and the boardwalk test (37157149149, 37156557872, 37156482178, 37156450959); five sim files were missing from it. A test file the table does not know is now planned at the table's mean time (47 s for sim) instead of its median (9.5 s), and the plan step names every such file in a warning, an annotation on CI, so the next new slow test cannot quietly overload a slice. And the plan now counts every batch reader's own time: it used to count only the longest one, so the slice holding them was planned at 387 s and took 537 s. Planned seconds per slice, both plans priced on the refreshed table: sim 421 / 223 / 329 / 338 before, 333 / 285 / 286 / 285 after (the 15 batch readers, which must share a slice, are the 333 s floor); browser 396 / 414 / 387 / 451 before, 406 / 407 / 407 / 405 after. Docs updated: engineering.md's slice notes.

A map, model or scenery file that fails to load is now tried again a few times, and when it still will not load the game says so. Before, one failed San Francisco map file left the region with no routes and no word, and the game never tried again. Now a failed file is fetched again up to three more times, waiting longer each time (and as long as the server asks when it is busy), and if the region still does not load, a card at the top says "San Francisco did not load. Check the connection, then tap Retry." with a Retry button.

For devs: `[default]`, not phone-verified, no local browser run (CI runs the browser tiers). Polish lane K2, from the playtest 4 run A second fix check (one failed map file with no deploy left 0 routes for 15 s; run B saw the host answer 429 twice just after a deploy).
- **Retry** (`retryingFetch` in the new `src/platform/retry-fetch.ts`): `startOffline` wraps the page's `fetch` once, inside `watchFetches`, so every caller gets it (content/'s map and pack data, assets/' models and kits, audio/'s voices). A GET of a file under `assets/` that fails to connect, or answers 408, 425, 429 or any 5xx, is tried again after 500, 1500 and 4000 ms (`RETRY_DELAYS_MS`); a `Retry-After` (seconds or a date) longer than that backoff is waited out, and one longer than 8 s (`RETRY_AFTER_CAP_MS`) gives up at once. When it gives up it hands back the last answer, or rethrows the last error, untouched.
- **Not retried**: a 404 or 410 (#598's stale-build rule: it still goes to `recoverStaleBuild` through `watchFetches`, which now hears only a build file's final answer), any other 4xx, a file outside `assets/` (`sw.js`, the changelog), a non-GET, a request with the network off or already aborted.
- **The message** (`ui.offerRetry`, `src/app/load-retry.ts`): a failed region pick (it was silent before), the Keys' real roads at boot, the Race tap's region load (was a 4 s toast) and a career race's region load now show the card with a Retry button. Retry runs the same load again; picking another region, a load that works or starting a race hides it.
- **Tests**: `src/platform/retry-fetch.test.ts` (a scripted host and a recorded wait list, no wall clock: a 429 then success, a 500 then success, a dropped connection then success, a permanent failure after four tries, `Retry-After` as seconds, as a date and over the cap, the real Keys road loader on a host that answers 503 first, and controls: 404 and 410, other 4xx, files outside `assets/`, POST, network off, aborted, and the loader without the retry failing at the first 503) and `src/app/load-retry.test.ts`. Before the change 16 of the 17 retry cases failed (only the control that fails without the retry passed).

Big files can now live in the Hugging Face dataset repo instead of git, for the real rider and bike models (interview, 2026-10-02: "Real models now"). `assets.lock.json` pins one exact commit and each file's size and SHA-256; `npm run assets:fetch` and `assets:verify` download and check them into `.cache/assets/`; `assets:add` and `assets:upload` pin and upload a new file with the signed-in `hf` CLI. The build bakes every pinned file in under `assets/ds/<region>/` (fetching what is not cached), so the game loads them from its own site and offline play works as before; they reach the asset manifest as a new `dataset` source, by asset id, with an optional region (`datasetIndex(region)`). The size budget now counts models per region (at most 3 MB each), and the whole-build limit goes from 6 MB to 15 MB, the architecture's first-play ceiling, because each region's models load only when a race there starts; the build measured 5.4 MB before any of them. A tiny placeholder cube and the dataset card prove the round trip. Shared files touched: `package.json` scripts, `vite.config.ts`, `tsconfig.node.json`, and one line in `src/app` that adds the dataset rows to the manifest.

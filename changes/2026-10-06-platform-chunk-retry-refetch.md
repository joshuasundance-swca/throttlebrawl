A part of the game that failed to download mid-race (a dropped connection on the phone) is now really downloaded again. Before, the browser remembered the failure and the second try never left the phone, so the part (the race's effects, the landmarks, the scenery's models) stayed missing until you reloaded the page.

For devs: polish batch K's live check, mustFix 1. In Chromium a failed `import()` is kept under its URL: the 2nd and 3rd imports of a chunk whose first request dropped or answered 404 threw at once with 1 request in all, while the same URL plus `?retry=1` loaded. So `loadChunk`'s retry and render/'s ask at the next `setRoad` never reached the network. `loadChunk` (`src/content/lazy-chunk.ts`) now reads the failed module's URL from the browser's words (`failedChunkUrl`: Chromium's "Failed to fetch dynamically imported module: <url>", Firefox's "error loading dynamically imported module: <url>"; the page's origin only) and retries by importing that URL with `retry=<n>`, a new number at each ask, so it is a request every time. That is safe because the failed module never ran. A chunk fetched that way is kept, so a later load of it takes the same module with no wait and no request, and two loads at once share one retry. A failure that names no URL (WebKit) tries the same import once more, as before. The retry returns the module itself, so each `loadChunk` load must be one bare `import()`: render/backdrop's two `Promise.all` loads are split into one `loadChunk` per chunk, and its JSON globs drop `import: 'default'` (the callers read `.default`). `rendererStats().eventProps` is now left out until the race parts' chunk is in (as its type allows), so a spec can see that chunk arrive. Tests: `src/content/lazy-chunk.test.ts` models the browser's module map (every answer kept under its URL, requests counted): the old retry (the same import again) gets 1 request and fails, the new one fetches `?retry=1` and loads; a later load reuses it; two at once share it; a chunk that is gone gives up and the next ask is a new request, `?retry=2`; no URL or another origin's falls back. `src/render/lazy-imports.test.ts` now also holds each `loadChunk` load to one bare `import()`, with a scanner control (it found the two backdrop loads before the split). New `tests/e2e/app-chunk-retry.spec.ts` (CI only): a control that imports the heat badge's chunk three times after a dropped first request (1 request, all three throw) and once with `?retry=1` (loads); the race parts' first request dropped, then the part appears with exactly one plain and one retried request; and the race parts answering 404 throughout: each race asks the host again by a new URL, a race with no deploy offers nothing, and after a simulated deploy (the worker file names another build) the result offers the reload. Built on #650's branch, merged with main after #650 landed. First-load JavaScript 473.7 KB gzip, 26.3 KB headroom, +298 B against main at f13f6d0 (local build). Not phone-verified, and other browsers' handling of a failed import is not checked: a shared chunk that failed under a chunk still fails its retry (the browser keeps that failure too), and only a reload clears it.

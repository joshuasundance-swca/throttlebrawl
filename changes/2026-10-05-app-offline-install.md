The game now works offline, and you can install it as an app. After the game has loaded once, it quietly saves a copy of itself on the phone (about 9 MB, once; after an update only the changed files download again), so the next time it opens and races with no signal at all. With a signal it always opens the newest build, as before; on a weak one it waits 3 seconds for the newest page, then opens the saved one. To install it, open the game's own address in Chrome and tap "Install app" on the menu: the button shows only while the browser offers an install, and nothing ever pops up on its own. Installed, it opens full screen and sideways with its own icon (a code-drawn motorbike, a placeholder until the real name and look). Firefox and iOS Safari have no install offer for a page to show; they still add it to the home screen from their own menus.

For devs: `src/platform/sw.ts` (the worker's entry) and `src/platform/offline-worker.ts` (its policy behind an injected cache and network, unit-tested in `offline-worker.test.ts`: install caches every file and fails only when `index.html` does not cache; hashed `assets/` files cross over from the last build's cache; activate drops older `offline-` caches only; the page, `changelog.json` and the manifest are network-first with a 3 s timeout; the rest is cache-first; other origins, other folders and non-GETs pass). `scripts/service-worker.mjs` builds the worker as `dist/sw.js` and prepends its config (cache name from the build id and a hash of every file's bytes, and every file the build wrote; tested in `scripts/service-worker.test.ts`); `vite.config.ts` adds the plugin. `src/platform/index.ts` adds `registerOfflineWorker` (after `load`, production builds only, silent on refusal), `createInstallOffer` (holds back `beforeinstallprompt`, prompts inside the tap; tested in `offline.test.ts`), `startOffline` and `installOffer`; `src/app/index.ts` wires them; `src/ui/index.ts` adds the hidden-until-offered `#menu-install` button. `public/` (new) holds the web manifest and the 192 and 512 px icons; `index.html` links them. A shared-config edit only this change needs: `playwright.config.ts` blocks service workers in every spec (a worker answering requests would hide them from `page.route()` stubs, and each spec would download the whole build), and `tests/e2e/app-offline.spec.ts` allows them: it loads the game, waits for the worker to take the page, checks every file the page loaded is cached (with a negative control), goes offline, proves the network is off with a fetch that must fail, reloads and races a bot to tick 120; a second test fires a synthetic install offer and checks the button shows, the banner was held back and only the tap prompts. The built `sw.js` was also run in Node against a fake worker global (661 of 661 files cached, offline page loads and hashed files answered, an unknown file failed, another site passed through). Browser specs were not run on the dev machine (CI runs them). Not phone-verified; the live Space's install and offline behaviour is unchecked until this deploys.

Isolated repeated-race runtime

Developer frame measurement can borrow the ordinary menu's renderer for a qualified, repeated
classic race. The runtime uses a separate seed, simulation, bot per repeat and graphics governor,
leaving the normal race, replay, career, settings and seed sequence parked. Audio is omitted and
an owned wake lease is required. Cancellation restores the saved menu presentation and publishes
one immutable result with commit and end times.

After returning from an ordinary race, restoration uses the menu's current snapshot without the
race interpolation history, matching the normal menu draw.

UI actions now reach one gate before changing their own local state. Radio shortcuts belong to
APP, which retunes and saves the live choice in one synchronous delivery; AUDIO no longer installs
independent key listeners. Delayed normal and UI completions cannot overwrite a newer owner.

Background road loading survives ordinary menu navigation. Pending requests remain visible to
measurement preflight until they settle; only the still-selected region can update routes, retry
notices or the backdrop. Selecting a previously loaded region adopts its cached roads.
Audio and control settings retain the road presentation; changing the visual look still applies
the complete presentation, and quality settings update the owned renderer token.

Focused checks cover ownership, preparation cancellation, real APP render/restoration wiring,
repeat isolation, listener ordering, quiet audio evidence, radio ownership and concrete UI actions.
This runtime does not qualify a phone, prove GPU completion or establish the launch performance bar.

The bundle train now says why a ready PR waits, blames a timeout only when the PR could have caused it, and routes docs-only PRs past the full suite with the train off. This one PR replaces two that overlapped (#588 and #590), with the fixes their reviews asked for.

- **Why a PR waits.** A PR whose quick check is green but that cannot ride yet (auto-merge not armed, a draft, or armed and in line) gets a note on a commit status of its own, `train`, which no rule requires: "waiting: arm auto-merge (gh pr merge --auto --squash) to ride the next train". Before, nothing on the PR said why it waited. The note is cleared once the PR rides, leaves the train path or merges. It never goes on `gate`: the review of #590 found that a pending `gate` note could outlive its reason (a PR reopened on the full path keeps it beside its passing `gate` check, and GitHub waits for both) and block a merge.
- **Timeouts.** A suite job that runs past its time limit now counts as red (GitHub reports it as cancelled, and the train used to conclude nothing and re-run the same bundle on every trigger). A bundle splits as for any red. A lone PR that timed out above cap 1 rides once more alone. At cap 1 it is blamed only if its diff can reach that job and main's own run of the job passed; otherwise nobody is blamed and it rides again once main moves. #590's own run is the case: browser 5/7 timed out on a diff of workflows, the train script and docs, which the browser tier never reads. Main's own timeout blames nobody. Re-running a timed-out main (#600) and reading it as red (#617) landed on main first; this PR now uses their one rule (`hitTimeout` and `ciState`, a run red only when every cancelled job timed out) instead of its own copy, and leaves `rerun-main.yml` as main has it.
- **Routing.** A docs-only PR takes the quick check as its gate whether the train is on or off (#575 ran the full suite while it was off). `README.md`, `space/`, `THIRD_PARTY_ASSETS.md` and anything under `public/`, `src/`, `packs/` or `tests/` ship, so they are never docs. "[full-gate]" counts only in the title or alone on a line of the description: #591 took the full path by accident from a sentence that mentioned it.
- **Safety.** The train's report prints the failing-test names it reads from a PR's logs only quoted, so no printed line can start with "::" and be read as a workflow command.
- **For contributors.** The README says what the game is instead of "a coloured test screen", and a new CONTRIBUTING.md explains what happens to a pull request, with what each `train` and `gate` line means.

This PR changes `.github/` (train.yml and ci.yml's comments), so it takes the full gate. Not phone-verified (no game change).

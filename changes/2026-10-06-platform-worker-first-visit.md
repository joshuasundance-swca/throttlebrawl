A first visit no longer downloads the game's first-load code twice. After the page loaded, the offline helper tried to reuse the files the browser had just downloaded, but the game's host labels every file "varies by origin", and the browser files the page's own script requests under a different label than the helper's, so it never found them and downloaded them again (about 0.5 MB of compressed copies on the last live check, counting the main script). The helper now asks for those files the ordinary way on a first visit: the browser checks with the host, the host answers "unchanged", and the browser hands over the copy it already has. A returning player's update still uses the compressed copies, and a deploy that lands mid-install still fails the install rather than mixing two builds. The deploy's compression check (`scripts/gzip-probe.mjs`) now samples every first-load script, including the two largest compressed copies, which the host sends via its file CDN, and it fails if that CDN stops letting the game read them. The worker config gains a `firstLoad` list, read from `index.html` by `scripts/service-worker.mjs`. Not phone-verified.

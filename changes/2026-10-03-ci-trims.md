CI does less repeat work. A push to main now skips the test suite when a green PR run already tested that exact tree: the PR run's gate records the tree it tested as an artifact, and main's new `plan` job looks it up. That path still runs the push-only checks (the squash commit's identity leak scan and a build with the prod stamp), boots that prod build in Chromium, and deploys as before. The prod build loads no draft packs while PR runs test with drafts loaded, so on that path a browser-only break past the boot that needs a draft entry is no longer caught on main; docs/engineering.md records the trade-off. `deploy-prod` and `release` now open their `if:` with `!cancelled()`, since a job skipped by its own `if:` is now always upstream of them and GitHub's implicit `success()` would otherwise skip every deploy; a test checks that rule for every job. Any doubt, or a main that moved after the PR's run, runs the whole suite. `gate` accepts a skipped suite only on that path, so a failed or cancelled job still fails it (`scripts/tested-tree.mjs`, with tests). Of the last 20 merges, 12 had the tested tree and would have skipped. The sim tier goes from 3 slices to 4, since its slices sat at up to 9.8 of their 10 minutes, and `tests/timings.json` is re-measured from 3 green main runs. `staging.yml` is retired after 0 requests since it went on-request; the staging Space itself is untouched and keeps its last build. This replaces the `[decided]` on-request staging plan; the maintainer listed retiring the staging workflow as next work on 2026-10-03.

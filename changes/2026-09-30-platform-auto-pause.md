platform-2 (auto-pause everywhere), the platform half. `platform/` gains the Screen Wake Lock: `keepAwake(on)` says whether a race wants the screen kept on, and the lock is held only while that is on, the page is visible and no pause reason stands (a hidden page, `pagehide`, a lost fullscreen or the rotate screen). It is re-requested whenever the page comes back while a race still wants it, released on pause and in menus, released again if it arrives after the race stopped wanting it, and never retried in a loop when the browser refuses it. `wakeLockHeld()` reports whether it is held, for the debug report and M5's soak. A browser without `navigator.wakeLock` simply never holds it. The existing pause signal (`watchLifecycle`'s `onHidden(reason)` for `visibility`, `pagehide`, `fullscreen` and `rotate`) is unchanged and is what `app/` receives. A new browser test proves `pagehide` alone pauses the race and that `pageshow` lands on the pause screen. Still to wire, in app-4: call `keepAwake(true)` when a race starts or resumes and `keepAwake(false)` on pause and in menus, and ask replay-2 to write the recording on `onHidden`; the browser tests for the mocked wake lock and the written recording land with that wiring.

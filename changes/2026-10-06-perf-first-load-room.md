The game's first download is 28.8 KB smaller (gzip), and the phone no longer checks every pack file against its schema before the first screen. The build now does that check, so the first-load JavaScript went from 485.8 KB to 457.0 KB of its 500 KB budget: 43.0 KB of headroom, up from 14.2 KB. No feature, content or sim rule changed.

For devs: the loader ran Zod over every bundled pack file at boot, which put Zod and the pack schemas (about 29 KB gzip) in the first load. A production build now runs the same check (`src/content/validate.ts`, via `src/content/pre-parse.ts`) on every pack JSON the bundle imports and every road data file it ships. It writes Zod's output in the file's place and fails on any finding (`scripts/pre-parse-packs.mjs`). The page's loader gets `src/content/validate-prebuilt.ts`, which only copies what it is given. `parse.ts` still runs its filename, folder and duplicate-id checks. Dev, the tests and `packs:check` run Zod as before. `src/content/validate.test.ts` checks all 3 packs (513 files) and finds the same parsed packs, registries (key order included, drafts on and off) and content hashes on both paths. Its negative control shows the comparison catches a file the build did not pre-parse (482 of the 513 change, mostly Zod's key order). `scripts/first-load.test.ts` now fails if Zod or the schemas reach the first load. It also checks that each of the 229 road data files the build ships is the pre-parse of its file on disk.

To keep the schemas out of the bundle, the plain data the registry and hashes read (`RESERVED_TYPES`, `SIM_EXCLUDED_FIELDS`, `VETOABLE_ITEMS`) moved to `src/content/schema/tables.ts`. The rider lists (`AI_STYLES`, `SIGNATURE_MOVES`, `LAW_HABITS`) moved to `vocab.ts`. Every name is still exported from `src/content/schema` and `src/content`, so no import elsewhere changed.

The perf check now names the 15 biggest first-load modules, each with its estimated share of the gzip size. With main measured, it also names the modules that grew by 0.5 KB or more (`scripts/first-load-modules.mjs`; the build writes `.cache/first-load-modules.json`). The shares add up to the budget's figure. The growth list starts working once main's build writes the list, which is after this PR lands.

Not affected: the sim content hash and full content hash (the same on both paths). The sim's source and its replay hashes are unchanged. **One-time cost:** the sim chunk's code hash, the code half of the replay key, moves once. Three `core/` constant lists that only the schemas read (`routes.ts`, `smashables.ts` and part of `surfaces.ts`) are no longer bundled. So a race saved mid-way on the previous build will not resume after this deploy, as after any sim-code deploy. The pack check (`packs:check`) is unchanged. Docs updated: `docs/content-packs.md` (Validation, as built), `docs/architecture.md` (Content registry) and `docs/engineering.md` (perf check). Not phone-verified.

# Riding readability and voiced subtitles

`[default]` Complete the remaining desktop evidence for rider identity and voiced subtitles before expanding content. This is a bounded acceptance pass using existing models, clips, renderer observation and UI seams. It does not generate replacement assets or establish human recognizability, acting quality or phone acceptance.

## Automated acceptance

- Derive voiced bark lines from the shipped packs using release-loaded set, line and speaker statuses (unset or `live`). Exclude vetoed voices; audio `draft` is review metadata and an existing draft clip still plays. Exercise every selected real content reference through the production ticker in a real race at Largest text on a 915 by 412 viewport. Do not duplicate the current line count or copy its words into the test oracle.
- Require each real clip's successful completed response, then redisplay the same line through the production cache and require a fresh matching decoded-voice start event. At that event, require the exact subtitle text/reference, the status accessibility role, and a visible strip. This is prepared playback: the existing late-clip rule may discard a cold request after its moment has passed. Preserve existing cold first-use, stale-drop and acoustic controls; starting a source does not prove intelligibility or phone audibility.
- Measure nonempty text ranges for the visible subtitle and speaker tag: they fit the strip and viewport, use at most two text lines, and keep the road ahead and visible HUD controls clear. Record actual font size, fit mode, voice duration and rectangles. Prove the detector catches a deliberately narrowed strip and hidden speaker, then restore each control.
- Observe the eight approved base rider/bike pairings in actual moving races through the production perspective camera. Require actual entity identities, loaded production assets, nonblank framed per-entity pixels and an empty hidden-entity control; record distance, speed, scene, graphics settings and camera. An observation band selects evidence and is not a recognizability score.
- Preserve normal and grayscale world views alongside the earlier static reference sheet. A human reviews shape/contrast; different hashes or nonblank pixels alone do not establish distinctness.
- Keep production contracts, collision behavior, saves, controls and asset budgets unchanged unless a demonstrated fault requires a separate repair. Run the normal gate and one coordinated served-build check. Report desktop-browser and physical-phone evidence separately.

## Completion boundary

Fix demonstrated delivery or layout defects and record the scoped outcome. Human recognition at speed, phone legibility, thumb occlusion, real-phone audio and acting remain explicit playtest judgments. This pass does not hold road and region design discussions.

The first subtitle proposal required every cold transfer to start a voice. A served run stopped after a completed transfer without a start event; the precise cause was not established. That universal cold-start guarantee conflicts with the documented intentional late-clip discard policy. The prepared-playback case replaces that guarantee without relaxing exact text, exhaustive content selection, transport, decoded-start or geometry controls. It does not establish cold-download latency or replace the existing first-use and late-clip checks.
